## Exact Customer.io update approval

Prepare the recipient, subscription eligibility, exact subject/body, report version, client ID, reporting period and approved scope. Include the private source reconciliation reference. Jeremy reviews these before delivery. Any change invalidates approval. Immediately before send, recheck opt-out, reply/booking state, stop status and prior provider attempts. Record provider acceptance ID and later delivery result separately.

Do not send the synthetic report fixtures to real clients. Never infer that successful profile/event tracking means an email was delivered. An unknown response is an incident to reconcile, not permission to retry through another sender.

## CSV handoff

`npm run ops:prepare` generates `.ziaflow-ops/handoff/linear-issues.csv` and `roadmap.json`. The CSV has Title, Description, Status, Project and Labels columns; map these explicitly in the actual Linear import UI if available. Do not assume native importer compatibility or successful import. If mapping is unavailable, create issues from the descriptions. Record created issue IDs and never blindly repeat an import. Jeremy's ownership is in each description; set the actual assignee after confirming the workspace identity.
